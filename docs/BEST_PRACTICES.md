# Best Practices

Stable conventions only. Versions, commands, and folder maps live in [Using the playground](USING_THE_PLAYGROUND.md) and the code.

## React

Use Effects only to synchronize with something outside React (browser APIs, subscriptions, network). Derive during render; handle user input in event handlers. Prefer that over Effect chains. Keep experiment previews lazy.

To reset state when a prop changes, store the prop you last saw in state and compare during render, or give the component a `key`. Tell a parent about a change in the handler that made it, never from an Effect. When an Effect's listener or loop needs the latest props or callbacks without re-subscribing, wrap them in `useEffectEvent`. Copying a callback into a ref each render is the older workaround. A ref is still right for a plain value an animation loop reads every frame. `src/lint/effects.test.ts` enforces this, along with the React rules in `.oxlintrc.json`.

The React Compiler (`babel-plugin-react-compiler`, set up in `apps/web/vite.config.ts`) memoizes components and hooks at build time, so new code needs no `useMemo`, `useCallback`, or `memo` for speed. It skips any component that breaks React's rules, which the lint catches. It also skips `try`/`finally`, `delete` through `?.`, and `?.`, `??`, or ternaries inside a `try` block; keep those out of components and hooks, or move the code to a plain function. Imperative loops (canvas, SVG, WebGPU) belong in a plain function the Effect starts and stops, holding their per-frame state in locals there.

## Experiments

Author WIP in Experimental. Humans and agents may create `apps/web/src/experimental/ideas/<Name>/source.tsx` or Save from the UI. The app mints `project.json` when it is missing and reconciles digest and revision after source edits. Make Live asks for a Live folder and publishes only the portable component.

Portable components may use CSS Modules but must not import from `apps/web/src/app/` or `apps/web/src/lib/`. GPU ideas may import `@/gpu` (see [WebGPU with vgpu](WEBGPU.md)). Do not put WIP in `apps/web/src/live/shells/` or render ConfigurableShell in Experimental.

## Backend

The UI talks only to `PlaygroundApi`; do not scatter `fetch("/api/...")`. Put behavior in `apps/api/src/features/`. Keep `src/server/` limited to validation and routing.

For saved ideas, `project.json` owns metadata and `source.tsx` owns code. Publish from that saved project instead of accepting duplicate name or source data; the Live destination belongs only to the publish request.

## Motion

Use the springs in `apps/web/src/app/motion/transitions.ts` (`morph` for the Live deck and page scroll, `panel` for edge rails, `pill` for toggles) instead of one-off curves. Animate through the small in-house engine in `apps/web/src/app/motion/` (motion values, `animate`, and hooks that write styles on one shared frame loop); its springs are a faithful port of Motion's, checked against recorded Motion traces. CSS transitions share the same vocabulary: `cssMotion.ts` installs `--spring-<name>-duration` / `--spring-<name>-easing` (the spring sampled into a `linear()` curve) and `--reduced-motion-duration` / `--reduced-motion-easing` on the document, so use those instead of hand-written durations and curves. Motion should stay interruptible: retarget a spring rather than waiting for it to finish. Honor `prefers-reduced-motion` and `prefers-reduced-transparency`. See [UI Design](standards/ui-design.md).

Hold 60 fps on integrated GPUs. Measure transitions in real Chrome (frame gaps, long animation frames, a trace) before and after a change.

- Drive per-frame values with motion values, never React state. Re-rendering a page 60 times a second costs more than the animation.
- Animate `transform` and `opacity`. Add `will-change: transform` only while something flies, and cap how far off-screen layers scale; a huge first raster stalls the whole frame.
- Do not blur (`backdrop-filter`) a surface that moves over a flat color, and keep blur radii fixed while animating.
- Mount heavy content before it animates (idle pre-warming, or wait for a ready signal), so a transition never pays for first renders. The deck warms every card nearest first, in idle moments and as a transition, never while the camera flies or a page glides (`deck/mountPolicy.ts`): a card that is not warm yet flies as its tile and fills in once the camera lands. A phone's touch scroll runs on the compositor, so warming carries on through it.
- Run a Live component's frame loop on `visibleLoop` from `@/live/kit/visibleLoop` (GPU components use `pausableLoop` from `@/gpu`). It runs only while the card is on screen, and each frame returns what it wants next: `true` for another frame, milliseconds to wait, or nothing to sleep until `wake()`, so a still component costs nothing. Defer expensive resize work until the size settles, but never hide or hold what the card shows meanwhile: it would land and then pop.
- Never read layout (`clientWidth`, `getBoundingClientRect`) or set `ctx.font` inside a frame loop: after the deck has moved a card that frame, either one restyles the whole page. Read sizes in a `ResizeObserver` callback, keep them, and set the font when the canvas resizes. A canvas resized in that callback is cleared before the next frame's draw, so draw it there too.
- A card that changes its layout position in the same frame it drops a transform is scored as a layout shift by Chrome, even off screen. When a flight lands, the pages around the open one are placed that way, so they stay unpainted for that one frame (`placeUnseen` in `CardDeck`).
- In flight, a preview lays out every frame, blending its tile and page layouts, so its content never jumps in size (`fitPreview.ts`). Once one of its canvases is seen to resize with it, it steps instead: it lays out only at a few stops, neither side changing more than 20% between them, and the layout it lands on goes in a whole step before it arrives, so a canvas that redraws on resize does so a few times per flight, not every frame, and never as the card comes to rest. Either way, arriving lays nothing out again: once the morph lands, the layout the card will rest at is in place, and only its scale follows the card's spring to rest. That layout is worked out from the card before the stage has been measured there, so on a first visit it can be a fraction of a pixel out, and is set right once the card rests. A preview remembers how it rested against its card's size (the stage's padding and the content's overflow), so the layouts it blends stay right when the deck lays out for a new viewport, and it learns that only from a stage the browser has measured: a card placed off screen is not laid out, and until it has rested as a page its flight there fits each frame on its own. Keep `ResizeObserver` work in a component without a canvas cheap, since it runs every frame of a flight.

iOS Safari, where the deck scrolls and snaps the document itself (`apps/web/src/app/safari.test.ts` pins each fix):

- A programmatic scroll under `scroll-snap-type: mandatory` snaps back to the page a finger last left at the next layout. Turn snapping off, scroll, and turn it back on a frame after that scroll has painted (`CardDeck`'s `resumeSnap`).
- A `touch-action: none` region can outlive the style that made it, and swipes over it never scroll. Hold a page still with a cancelled `touchmove` instead.
- `touch-action: pan-y` still pans a diagonal swipe. A sideways control must cancel `touchmove` itself, before the finger passes Safari's pan slop.
- A press can fail to reach a button on the live site while LAN builds, Chrome on the same iPhone, and Playwright WebKit all receive it. A control that acts on press or hold also counts the tap's `click` when no press did (Word Clock's `windHold.ts`), and is tried on an iPhone against the live site.

`apps/web/src/lint/performance.test.ts` enforces these rules in `bun run test`. It parses each callback handed to `requestAnimationFrame` or `visibleLoop` and follows the functions and `this.` methods of the same file it calls, two calls deep; calls on other objects and into other files are not followed. In Live, any `requestAnimationFrame` or `setInterval`, and a function that re-schedules itself with `setTimeout`, needs `visibleLoop` or a reason. When an exception is justified, say why with a `perf-allow: <reason>` comment on the CSS rule, or on or just above the line of code. On the line above a call in a frame callback, it marks a call that runs only when something changed or at most every so often, such as a size check every 500 ms.

## Checks

`bun run lint` (oxlint, configured in `.oxlintrc.json`), `bun run typecheck`, and `bun run test` must pass before work is done; CI runs all three. The lint covers React's rules (hooks, refs, no state set in Effects), accessibility, and leftovers such as unused code and `console.log`.

`apps/web/src/lint/cards.test.ts` reads each preview with TypeScript's parser and holds every Live component to the slot the deck fills: `live/<folder>/<Name>/preview.tsx` beside a `<Name>.tsx` that exports `<Name>` (and no component folder without a preview), a `meta` typed `CardMeta` (or `FamilyMemberMeta` in a family folder, whose `family.ts` is typed `FamilyMeta`), and a default `<Name>Preview()` that takes no props, renders `<Name />`, and is the only other export. The deck then opens, flies, fits, pages, resets, and publishes it like every other card.

`apps/web/src/lint/standards.test.ts` enforces the house rules no off-the-shelf linter knows: Live components stay portable, lay out in their card's box (no viewport units or `position: fixed`), honor `prefers-reduced-motion`, gate hover styles behind `@media (hover: hover)`, and leave a swipe free to page the deck (`touch-action: none` only mid-gesture); filters settle on `filter: none` rather than `blur(0)`, which Safari leaves blurred; and no commented-out code. A component's own motion contract (shared timing, compositor-only properties) lives in a test beside it, such as `MenuPill.test.ts`. Live previews must fit a phone's page unscaled, with a `@media (max-width: 48rem)` layout where they are wider; CI checks it with `check:phone`, which also drags a Spacing Tidy square and Focus Pull's focus by touch. `check:flights` fails a flight between the grid and a page that lands with a jump or a late layout, or makes the cards around it score a layout shift. `check:gpu` fails a build that fetches the GPU library where WebGPU is missing. `check:idle` is a cold-idle regression check: it opens a still card's page once every card's preview has mounted and fails, naming the card, when any code keeps scheduling frames, short timers, or intervals more than about once a second while its card is off screen, however the loop was written. It does not see work started by interaction or work slower than that, which the lint and `visibleLoop` cover, nor `MessageChannel` loops or CSS animations, whose off-screen cost only a browser trace shows. It finds deck cards (by slug, since titles need not be unique), their fit stage, loading placeholder, load error, and mounted previews by `data-deck-card`, `data-deck-fit`, `data-deck-loading`, `data-deck-error`, and `data-deck-members`, as the other browser checks do (`scripts/deckCards.ts`), so a preview's own markup never confuses them.
